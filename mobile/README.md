# اپ موبایل حضور مِرآت

اپ اندروید/iOS برای ثبت ورود و خروج کارمندان با اثر انگشت گوشی خودشان.

- **Expo SDK 57 / React Native 0.86 / TypeScript**
- سه صفحه: ورود، صفحهٔ اصلی (تایمر + دکمهٔ ثبت)، سابقهٔ روزها
- رابط فارسی و راست‌به‌چپ، تاریخ و ساعت شمسی
- سرصفحهٔ اصلی ساعتِ زندهٔ **سرور** را نشان می‌دهد، نه ساعت گوشی

این اپ **کلاینت** سامانهٔ meraat است. سمتِ سرور هم آماده است: مسیرها در
`routes/api.php` و منطق در `app/Http/Controllers/MobileApiController.php`
(قرارداد کامل در [`docs/API.md`](docs/API.md)).

## اجرا در حین توسعه

```bash
cd mobile
npm install
npx expo start
```

سریع‌ترین راه دیدن نتیجه بدون نصب هیچ ابزار اندرویدی: اپ **Expo Go** را روی
گوشی نصب کنید و QR کد را با آن بخوانید (گوشی و کامپیوتر روی یک شبکه).
`expo-local-authentication`، `expo-secure-store` و `expo-crypto` هر سه در
Expo Go موجودند، پس ورود و ثبت اثر انگشت همان‌جا قابل امتحان است.

اگر `--tunnel` لازم شد و در دسترس نبود، `--lan` را امتحان کنید.

### اگر گوشی وصل نشد (خطای `Failed to download remote update`)

روی اندروید این خطا یعنی Expo Go نتوانسته manifest را از Metro بگیرد؛ نه
یعنی کد اپ خراب است. ترتیب بررسی:

```bash
npm run doctor:lan        # آدرس داخل QR، وضعیت سرور، فایروال، کارت‌های VPN
```

۱. **آدرس داخل QR را ببینید.** باید `exp://<IP کارت Wi-Fi>:8081` باشد. اگر
روی یک کارت مجازی (VPN مثل Hiddify، Docker، Hyper-V) افتاده، آدرس را دستی
تثبیت کنید:

```bash
REACT_NATIVE_PACKAGER_HOSTNAME=192.168.0.105 npx expo start --lan
```

۲. **در مرورگر گوشی** (نه Expo Go) `http://<همان IP>:8081/status` را باز
کنید. `packager-status:running` یعنی شبکه سالم است و مشکل از Expo Go یا آدرس
QR است؛ باز نشدن یعنی گوشی به این IP نمی‌رسد.

۳. اگر مرورگر گوشی هم باز نکرد، مقصر شبکه است، نه Expo:

- VPN روی گوشی خاموش باشد؛ بعضی کلاینت‌ها ترافیک شبکهٔ محلی را هم داخل تونل
  می‌فرستند. اگر خاموش‌کردن ممکن نیست، گزینهٔ «عبور از شبکهٔ محلی» را روشن کنید.
- گوشی روی دیتای موبایل یا SSID مهمان نباشد — همان SSID کامپیوتر.
- بعضی روترها ارتباط کلاینت‌ها با هم (Client Isolation) را بسته‌اند.
- فایروال ویندوز: اولین بار باید در پیام «Allow access» گزینهٔ Private را
  بزنید؛ `npm run doctor:lan` وضعیت قاعدهٔ ورودی `node.exe` را چاپ می‌کند.

۴. Expo Go را از استور به‌روز کنید و QR همان ترمینالی را بخوانید که
`expo start` بدون `--web` در آن اجراست؛ QR سرور وب (پورت ۸۰۸۳) manifest
نیست و در Expo Go کار نمی‌کند.

راه جایگزین وقتی هیچ‌کدام جواب نداد: `npx expo start --tunnel` (نیاز به اینترنت
دارد و روی گوشیِ بدون VPN در ایران معمولاً باز نمی‌شود) یا اتصال USB با
`adb reverse tcp:8081 tcp:8081` و بعد `npx expo start --host localhost`.

## آدرس سرور

پیش‌فرض `https://meraat.piqagram.ir/api/v1` است. برای عوض کردن، فایل `.env`
کنار `package.json`:

```
EXPO_PUBLIC_API_URL=http://192.168.1.50/api/v1
EXPO_PUBLIC_DEVICE_NAME=گوشی دفتر
```

`EXPO_PUBLIC_*` در زمان build داخل باندل نوشته می‌شود، پس بعد از تغییرش باید
دوباره build کنید (این متغیرها عمومی‌اند؛ هیچ رازی داخلشان نگذارید).

## بررسی و تست

```bash
npm test         # تست‌های منطق، با test runner خود Node
npm run typecheck
```

تست‌ها عمداً بدون هیچ فریم‌ورک اضافه‌ای نوشته شده‌اند: Node 24 خودش فایل
`.ts` را اجرا می‌کند، پس `jest` و `jest-expo` لازم نیست. به همین دلیل
importها در فایل‌های تست پسوند `.ts` دارند (خود Node پسوند می‌خواهد) و در
کد اپ ندارند (Metro پسوند نمی‌خواهد).

## ساخت APK

پیش‌نیاز روی ماشین build — **این ماشین هیچ‌کدام را ندارد**:

- JDK 17
- Android SDK (Build-Tools 35، Platform 35) و `ANDROID_HOME`
- متغیر `PATH` شامل `platform-tools`

```bash
cd mobile
npx expo prebuild --platform android      # پوشهٔ android/ ساخته می‌شود
cd android
./gradlew assembleRelease                  # APK در app/build/outputs/apk/release/
```

برای امضا، `android/app/build.gradle` را با یک `keystore` تنظیم کنید. کلید
امضا را گم نکنید: نسخهٔ بعدی اپ فقط با همان کلید روی نسخهٔ قبلی نصب می‌شود.

توزیع: دانلود مستقیم APK از خود سایت، یا بازار/مایکت. EAS Build ابری برای
ایران قابل اتکا نیست (پرداخت با Stripe و دسترسی شبکه‌ای)، پس مسیر local
توصیه می‌شود.

## ساخت آیکون‌ها از لوگو

آیکون اپ یک فایل نیست، پنج فایل است: آیکون اصلی، لایهٔ پیش‌زمینه و پس‌زمینهٔ
اندروید (آیکون تطبیقی)، آیکون تک‌رنگ تم و فاوآیکون وب. همه از یک لوگو ساخته
می‌شوند و اسکریپتشان در مخزن است:

```bash
powershell.exe -NoProfile -ExecutionPolicy Bypass \
  -File tools/make-icons.ps1 -Source "C:\path\to\logo.jpg"
```

اسکریپت روشنایی تصویر را می‌گیرد، بزرگ‌ترین شکلِ به‌هم‌پیوستهٔ تیره را پیدا
می‌کند (متن‌های ریز حاشیه دور ریخته می‌شوند)، سوراخ‌های داخلش را پر می‌کند و
از همان «نقاب» هم شفافیتِ لایهٔ اندروید و هم آیکون تک‌رنگ را می‌سازد. نتیجهٔ
نهایی در `assets/` می‌نشیند و نسخهٔ کوچک لوگو هم برای ساخت دوباره در
`assets/brand/logo-source.jpg` ذخیره می‌شود.

## تصمیم‌های طراحی

**چرا صفحهٔ ورود هم همان سرصفحهٔ سبز را دارد.** قبلاً ورود زمینهٔ روشنِ یکدست
داشت و بالایش لوگوی شناور بود؛ اپ دو چهره می‌شد و ورود شبیه یک فرم وب به نظر
می‌رسید. حالا همان ساختار صفحهٔ اصلی است: سرصفحهٔ سبزِ تیره با گوشه‌های گردِ
پایین (نشان، نام اپ، و **همان دو لکهٔ نوری** — مشترک در `HeroGlows`)، بعد
کارت‌های سفید. شرط‌های امنیتی هم از چند پاراگرافِ خاکستری به کارتِ «امنیت و
شرایط ثبت» با سطرهای کوتاه تبدیل شدند؛ اینها «شرط»اند و کسی که می‌خواهد
بداند چرا ثبتش رد شده، دنبال یک جمله در میان متن نمی‌گردد.

**چرا سرصفحه ساعت را نشان می‌دهد و «داشبورد» نه.** بالای صفحه سه چیزِ
به‌درد‌بخور نشسته است: نام و نقش کارمند، ساعتِ زندهٔ سرور، و تاریخِ سرور. برای
اپی که کارش ثبت زمان است، «الان ساعت چند است از نظر سرور» مهم‌ترین اطلاعات
بالای صفحه است — و همان‌جوری که نشان «مرجع زمان: سرور» می‌گوید، این ساعت از
گوشی نمی‌آید.

**چرا تایمر دقیقه‌ای نبود.** جمع کارکرد داخل `workedSeconds` حساب می‌شود و
`workedMinutes` فقط همان را به پایین گرد می‌کند. اگر مبنا دقیقه بود، تایمر
زنده تا یک دقیقهٔ کامل تکان نمی‌خورد؛ با مبنای ثانیه، عدد همان‌طور که کاربر
انتظار دارد هر ثانیه جلو می‌رود.

**چرا دکمهٔ ثبت کوچک شد.** ارتفاعِ ۱۳۲ پیکسلی (بلوک بزرگ) دکمه را از حد
استاندارد بیرون می‌برد و روی صفحه‌های کوچک فضا می‌خورد. ارتفاع فعلی ۵۶ است
(اندازهٔ استاندارد دکمهٔ اصلی)، و توجه را به‌جای اندازه، دو چیز جلب می‌کند:
حلقهٔ آرامِ دور آیکون انگشت و رنگِ متفاوتِ ورود/خروج.

**چرا حرکت‌ها با `Animated` خودِ React Native.** سه صفحه با چند ورودِ نرم
نیازی به کتابخانهٔ انیمیشن ندارند. `src/components/motion.tsx` چند چیز دارد:
`FadeInView` (محو + چند پیکسل بالا آمدن)، `PulseHalo` (حلقهٔ تپندهٔ دور آیکون
انگشت)، `DriftGlow` (لکهٔ نوریِ سرصفحه) و `useGlowPush` (همان لکه‌ها وقتی انگشت
روی سرصفحه کشیده می‌شود). همه فقط opacity و transform را عوض می‌کنند تا روی نخ
رابط کاربری اجرا شوند؛ روی وب `useNativeDriver` خاموش است چون آنجا ماژول بومیِ
انیمیشن وجود ندارد.

**چرا حسابِ لکه‌ها جدا شد.** قاعدهٔ «هر لکه خلافِ کشیدنِ انگشت برود و لکهٔ
نزدیک‌تر بیشتر» یک حسابِ ساده است، پس در `src/lib/glow.ts` نشسته و تست جدا
دارد؛ `useGlowPush` فقط همان عدد را روی `Animated` می‌نشاند. مبنای جابه‌جایی،
فاصلهٔ انگشت از *نقطهٔ شروعِ لمس* است نه سرعتِ لحظه‌ای: با سرعت، رفتار روی
گوشیِ ۶۰ و ۱۲۰ هرتز دو چیز می‌شد. جای کادر هم با `measureInWindow` خوانده
می‌شود، چون در React Native مقدار `locationX` هر لمس نسبت به عمیق‌ترین ویویی
حساب می‌شود که لمس رویش افتاده، نه نسبت به سرصفحه.

**چرا اثر انگشت، و چرا «یک کارمند، یک گوشی».** الگوی اثر انگشت داخل
Secure Enclave / TEE دستگاه می‌ماند و هرگز بیرون نمی‌آید؛ API سیستم‌عامل فقط
می‌گوید «یکی از انگشت‌های ثبت‌شدهٔ همین گوشی تطبیق خورد» — نه کدام انگشت.
پس اپ نمی‌تواند کارمند را از خودِ انگشت تشخیص دهد. کاری که می‌کند این است که
هر گوشی به یک حساب بسته می‌شود و برای هر ثبت، تطبیق اثر انگشت **روی همان
گوشی** لازم است. جزئیات در `docs/API.md`.

**چرا ساعت گوشی مرجع نیست.** زمان حضور را سرور تعیین می‌کند
(منطقهٔ +03:30). اپ برای نمایش «کارکرد تا این لحظه» ساعت سرور را در لحظهٔ
دریافت پاسخ *لنگر* می‌کند و بعد فقط گذشت زمان را اضافه می‌کند؛ این‌طور ساعت
اشتباه گوشی یا ناحیهٔ زمانی دستگاه روی محاسبه اثر نمی‌گذارد.

**چرا ناوبری دستی است.** `AGENTS.md` که خود Expo ساخته `expo-router` را پیشنهاد
می‌دهد. برای سه صفحه با جریان خطی، یک سوییچ ساده کافی بود و پنج وابستگی
کمتر یعنی نصب و به‌روزرسانی مطمئن‌تر روی شبکه‌ای که دسترسی به npm در آن روان
نیست. اگر صفحه‌ها زیاد شدند، مهاجرت به `expo-router` کار سختی نیست.

**چرا `I18nManager.forceRTL` استفاده نشده.** آن یک تنظیم نیتیو است که با هر
build باید دوباره اعمال شود و اگر جا بماند چیدمان بی‌سروصدا برعکس می‌شود؛ به
جایش استایل‌ها صریح راست‌به‌چپ نوشته شده‌اند (`row-reverse` /
`textAlign: 'right'`).

**چرا فونت اختصاصی باندل نشده.** فونت پنل وب `IRANSansWeb` با فرمت `woff2`
است و React Native فقط `ttf`/`otf` را می‌فهمد؛ فونت پیش‌فرض سیستم برای فارسی
کافی است. اگر خواستید، فایل ttf را در `assets/` بگذارید و با
`expo-font` بارگذاری کنید.
